## 问题（用户反馈）

1. Play 中底部绿色进度条不动。
2. 死亡重开后，面板的等级和经验计数不对。

## 根因

### 现象 1：无 Source Image 的 `Image`，`type` 与 `fillAmount` 不生效

`ExpBarFill` 用 `Image.Type.Filled` + `fillAmount` 表示进度。但 **Unity 的 `Image` 在没有 Source Image 时，`OnPopulateMesh` 会直接走 Simple 的全矩形绘制，`fillAmount` 被完全忽略**。本工程美术全是无 sprite 的占位色块，因此该条**永远画满、永不变化**。

`fillAmount` 在数据层一直是正确的（实测 Ready 阶段为 0），只是渲染层不认。

### 现象 2：`Reset()` 静默归零，HUD 监听收不到通知

`GameStateModel.Reset()` 用 `SetValueWithoutEvent` 归零——这是迭代 5 修复 3 为防「重开时 `Level` 置回触发升级面板误弹」刻意做的。副作用：**HUD 的监听不会触发**，于是重开后等级/经验文本仍停在上一局的值。

时间/波次/击杀会在一两帧内自愈（数值持续变化会重新触发），而**等级与经验只在拾取/升级时才变**，故会长时间显示错误值。绿色进度条同理——重开后不回到 0，表现为「不动」。

## 修复

1. **经验条改用锚点宽度表示进度**：`HudController.RefreshExp()` 不再用 `fillAmount`，改为设置 `ExpBarFill` 的 `RectTransform.anchorMax.x = exp / threshold`（`anchorMin = (0,0)`、`anchorMax.y = 1`、四周 offset 归零）。无 sprite 时 `Image` 会按矩形实际大小画满，锚点宽度即进度。
2. **`ExpBarFill` 的 `m_Type` 从 `Filled` 改回 `Simple`**（无 sprite 时 Filled 无意义，留着会误导后续维护者）。
3. **进入局内时主动刷一次 HUD**：`HudController.OnPhaseChanged()` 在 `phase == Playing` 时调用 `RefreshTop()` + `RefreshExp()`。开始与死亡重开都经此路径，无需在 `StartNewGameCommand` 里新增耦合。

## 影响范围

- 修改：`Controller/HudController.cs`
- 预制体：`Prefabs/HudPanel.prefab`（`ExpBarFill` 的 `m_Type`、`m_FillAmount`、占位锚点）

## 验证结果

- ✅ **编译通过**：0 错误 0 警告。
- ✅ **受控实验确认根因**（Play 模式实时截图，非残留帧）：把 `StartMenuPanel` 的全屏 `Image` 设为 `type = Filled` + `fillAmount = 0.4`，画面仍被 100% 覆盖，右侧应透明的 60% 无任何透出 → 证实 `fillAmount` 在无 sprite 时不生效。
- ✅ **修复后机制生效**（运行时实测）：Ready 阶段 `ExpBarFill` 的 `anchorMax = (0, 1)`、`rect.width = 0.00`，填充宽度已跟随 `exp/threshold` 归零。
- ✅ **阶段状态正确**（运行时实测）：Ready 下 `StartMenuPanel` 激活、`HudCanvas` / `ChoicePanel` / `GameOverPanel` 均未激活。
- ✅ **运行零错误**。
- ⏳ **待人工确认**：进度条随拾取经验增长、升级后正确回零、死亡重开后等级/经验/进度条同步归零。这些均需进入 Playing 阶段，而 `unity-skills` 无输入模拟能力。

## 过程记录（一次自我推翻，值得记录）

诊断过程中我一度被**编辑器的残留 Game View 帧**误导：

- `scene_screenshot` 在编辑模式下返回的是「最后一次渲染的画面」，且 PNG 是延迟写入的。我取出的一张图里绿条显示约 35%，据此我一度**推翻了自己正确的判断**，认为 `fillAmount` 是生效的。
- 事后确认：那张图实际是在编辑器下一次重绘时才真正捕获的，此时我已把占位锚点改成 0.35，拍到的是**锚点效果**，与 `fillAmount` 无关。
- 更早的 `fillmode_test.png` 同样是不可靠的残留帧——它显示 HUD 可见、开始界面消失，与当时真实的 Ready 状态（实测 `HudCanvas` 未激活）相反。

**教训**：编辑模式下的截图（以及延迟写入的截图文件）不能作为运行态证据。判断运行态应以 `editor_playmode_inspect` / 层级查询等**可量化的实时数据**为准，必要时用 Play 模式下的实时截图（`isPlaying=true`）并确认其与已知状态自洽。这条与上一次修复中「截图看不见 ≠ 没生成」的教训是同一类问题。
