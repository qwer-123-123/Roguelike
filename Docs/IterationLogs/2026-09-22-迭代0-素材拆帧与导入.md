## 关键步骤

1. **写拆帧工具** `Docs/Design/_tools/split-frames.ps1`：读 `Docs/Design/h5/assets/` 下的精灵条，按帧宽切分，输出到 `Assets/Art/`。帧数表沿用 H5 的 `assets.js`（unit idle 8 / walk 6 / atk 5~12 / death 6；enemy walk 9 或 8、atk 9~16、death 6~14）。

2. **产出锚点换算表**：脚本同时输出 `Assets/Art/Manifest.csv`，逐帧记录 `frameW/frameH/refH/worldHeight/scale/offsetY`。这是「离线加工」与「编辑器批量导入」之间唯一的桥 —— 1007 个资产的参数不能散在人脑里。

   换算严格等价于 H5 `play/js/assets.js` 的 `drawSprite`：
   ```
   scale   = worldHeight × 100 / refH        # PPU 取 100，尺寸由 SO 的 scale 决定
   offsetY = (frameH / 100 × scale − worldHeight) / 2
   ```

3. **单图资源直接复制**：UI 零件 182 + 窗口 6 + 图标 17 + 背景 2、道具 15、头像 4、地形 52。

4. **批量设置导入参数**：`texture_set_settings_batch` 一次提交 1007 项，21.8 秒完成，0 失败。

5. **给 `Assets/Art/` 加保护性 `.gitignore`**：本仓库当前是**公开**的，而素材许可（策划案 R11）未读 —— 当初 `Docs/Design/h5/assets/` 正是为避免公开再分发才从全部历史中摘除。已告知用户，用户正在把仓库改为私有；**确认后需删掉该忽略行并提交素材**。

## 设计决策

- **拆帧而非切片**：`unity-skills` 没有切图操作（`spriteMode=Multiple` 能设，但定义子精灵矩形没有对应技能），而手写 `.meta` 在本引擎上必然失败 —— 该引擎的 `.meta` guid 被混淆过，与 YAML 里引用的 hex guid 无推导关系。
- **`filterMode` 保持默认 Bilinear，不用 Point**：素材是手绘风不是像素风，Point 会让边缘锯齿。真正必须改的是 `textureType`（默认是 Default，不改就没法当精灵用）。
- **`PPU = 100` 统一值 + 尺寸交给 SO 的 scale**：`sprite_set_import_settings` 没有批量版，若逐个设 PPU 需要 1007 次 REST 调用（外加 1007 次重导）。改成「统一 PPU + SO 控尺寸」后，导入只需 3 次批量调用。
- **不做离线重采样（见下方遗留说明）**：先走通管线，重采样留作优化。

## 遗留说明

**显存占用偏高，建议在迭代 2 之前处理。** 实测原始像素 42.5 Mpx，未压缩 RGBA32 约 **170MB 显存**。桌面端能跑，但迭代 2 要上「同屏 80 只敌人」时会撞上。

根因是没有做离线重采样：`enemy/walk_*` 一律按 210px 归一化（这样 BOSS 与小僵尸用同一套画布尺度），而 z1 的显示倍率只有 0.643 —— 相当于存了 2.4 倍冗余的像素。

修法：在 `split-frames.ps1` 里按角色乘上重采样系数（只缩不放），可降 4~6 倍磁盘与显存。**代价是所有 `scale` / `offsetY` 要重算重导**，所以越晚改越贵 —— 这正是计划里「素材一次做对」那条推荐的由来。

**其他遗留**：
- 工程仍无中文字体（策划案 R6），迭代 1 的兵种选择界面会立刻撞上
- 仓库仍是公开的，`Assets/Art/` 处于忽略状态；改为私有后需移除忽略行并单独提交素材
