## 根因：移植 H5 时把锚点写在了旋转之外

H5 原型的绘制顺序是**先旋转、后偏移**，偏移量因此落在「已旋转」的空间里：

```js
ctx.rotate(rot);
ctx.drawImage(img, -dw/2, -dh + hUnits*0.5, dw, dh);   // 偏移在旋转之后
```

我在 Unity 里把同样的偏移写成了 `Visual.localPosition`。但 **`localPosition` 是父空间坐标，不受自身 `localRotation` 影响** —— 于是补偿量永远朝世界里固定的「上」，而帧内容的偏移是跟着角色朝向一起转的。两者一错开就产生位移。

**为什么攻击时最明显**：攻击帧比待机帧高（手枪 204px vs 135px），补偿量 `offsetY` 达到约 0.45 格（约 48 像素）。待机/行走时补偿量接近 0，所以看不出来。

**为什么是「向后」**：位移方向是「世界固定上」与「角色朝向」之间的夹角方向，随朝向变化；用户观察到的是其中一种朝向下的表现。

**为什么第一版没发现**：验证时用的是固定朝向的静态截图，没有「转向 + 攻击」的组合。

## 修法：把 SpriteRenderer 下沉到子节点

```
Visual        （CharacterView：只负责旋转与翻转）
└── Sprite    （SpriteRenderer：承载 offsetY，随 Visual 一起转）
```

`CharacterView.ApplyTransform()` 改为把 `offsetY` 写到持有 `SpriteRenderer` 的那个节点上；`Visual` 自身位置恒为原点。保留了对旧结构（SpriteRenderer 与 CharacterView 同节点）的退路分支，避免破坏既有预制体 —— 但正确结构一律是两层。

两个编辑器工具同步更新：`SceneWirer`（玩家）新建 `Visual/Sprite` 并移除 `Visual` 上误挂的 SpriteRenderer；`EnemyPrefabBuilder`（敌人）直接建两层。

## 影响范围

- 修改：`Assets/Scripts/Controller/CharacterView.cs`
- 修改：`Assets/Editor/SceneWirer.cs`、`Assets/Editor/EnemyPrefabBuilder.cs`
- 预制体：`Enemy.prefab` 重建（新增 `Sprite` 子节点）
- 场景：`Main.unity` 的 Player 补出 `Visual/Sprite` 子节点

## 验证结果

- ✅ **编译 0 错误**、运行态 0 错误
- ✅ **结构正确**：场景与敌人预制体各有 1 个 `Sprite` 子节点；`Player/Visual` 的 `childCount = 1`，`Player/Visual/Sprite` 挂 `Transform + SpriteRenderer`
- ✅ **数值逐位对上**（这是关键证据）：

  | 检查 | 实测 | 手算 |
  |------|------|------|
  | `Player/Visual` 世界位置 | `(0, 0, 0)` | 应恒为原点 ✓ |
  | `Player/Visual` 旋转 | 87.36° | — |
  | `Player/Visual/Sprite` 世界位置 | `(-0.1174, +0.0054)` | `R(87.36°)·(0, −0.0907) × scale 1.2963` = `(0.1174, −0.0054)`，朝向 177° 触发翻转取反 = `(−0.1174, +0.0054)` ✓ |

  偏移确实随 Visual 的旋转与缩放一起变换了 —— 修复前它会是固定的 `(0, offsetY)`。

## 遗留说明

- **本次验证用的是数值断言而非肉眼观察**。`Visual` 恒在原点 + 偏移随旋转变换，这两条同时成立即等价于「角色不再因转向而位移」。但**仍未在「转向 + 攻击」的连续动作下目视确认**，建议试玩时重点看这一条。
- 上一轮记的「敌人攻击动画没用上」仍然有效：敌人始终播 Walk，接触伤害是瞬时的。
- 完整地貌过渡（`TILE_MASK`）仍留给迭代 4。
