## 关键步骤

1. **HUD 预制体化**：新建 `Prefabs/HudPanel.prefab`（`HudCanvas` + HP / Time / Wave / Kills / ExpBarBg(ExpBarFill) / Exp）。`HudController` 删除 `CreateUI()` / `MakeText()` / `MakeImage()`，改为 6 个 `SerializeField` 引用（`hpText` / `timeText` / `waveText` / `killsText` / `expText` / `expBarFill`）＋原有的 `playerInput`。
2. **升级面板预制体化**：新建 `Prefabs/UpgradePanel.prefab`（`UpgradeCanvas` + `ChoicePanel` + `Choice0~2` 各带标签）。`UpgradePanelController` 删除全部建 UI 代码与 `using UnityEngine.EventSystems`，改为 `panel` + `choiceButtons[]` + `choiceTexts[]` 三个序列化引用。选项按钮/文本改用**数组**，不再硬编码 3 个字段。
3. **补回 EventSystem**：升级面板原是工程中**唯一**创建 `EventSystem` 的地方。那个 `CreateUI()` 被删除后，若不再补，四个界面的按钮会全部失效。改为在场景中放一个常驻 `EventSystem` 对象（含 `StandaloneInputModule`）。
4. **删除旧对象**：移除场景中遗留的 `HUD` 与 `UpgradePanel` 两个空壳对象（它们的组件早前已失效）。
5. **可见性职责从 Canvas 转到根对象**：原先隐藏的是运行时新建的 `HudCanvas`；预制体化后改为 `gameObject.SetActive(...)` 隐藏 `HudCanvas` 根对象本身，对预制体实例而言更直观。

## 设计决策

- **`playerInput` 保持运行时查找**：`HudController` 需要引用场景中的 `Player`，而预制体**无法跨对象引用**（引用场景对象会破坏预制体）。故该字段在预制体里留空，由 `Start()` 的 `FindObjectOfType<PlayerController>()` 填充。
- **选项数组而非固定字段**：`choiceButtons[]` / `choiceTexts[]` 用数组，选项数量变化时只需改预制体，不必改脚本字段。
- **新增 `EventSystem` 放在场景而非预制体**：全局只需一个，放进任一预制体都会产生「实例化了才有」的隐式依赖；放场景中职责最清晰。
