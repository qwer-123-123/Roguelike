## 问题一：地图是黑的

**性质**：不是缺陷，是**尚未实现** —— 地形原本排在迭代 4（计划的迭代总览里顺序是 1，可并行），而迭代 0~2 只导入了瓦片，没往场景里铺。

相机是纯色深底 + 场上没有任何地面对象，所以看过去就是一片黑。

**这一轮先做了最小可用版**（编辑器工具 `Tools ▸ Game ▸ Build Ground`）：

- 用 `SpriteRenderer` 的 **Tiled 平铺模式**，一张 89px 的草地瓦片铺满 48×48 世界单位
- 上面撒 40 个裂纹贴片做变化（固定种子 `20260924`，可重跑且布局一致）
- `sortingOrder` 分别为 `Ground = -1000` 与 `GroundDetail = -800`

**为什么用 Tiled 而不是烘焙整块贴图**：按 1080p 下 108 像素/单位的屏幕密度，48×48 的场地烘焙成一张贴图要 5184² ≈ **107MB 显存**；Tiled 模式**不占额外显存**，且更清晰。代价是单一瓦片、没有自动拼接的地貌过渡。

**Tiled 模式的一个要求**：sprite 的 mesh 必须是 `FullRect`（默认 `Tight` 会静默退化并打警告）。注意该字段不在 `TextureImporter` 上，要经 `TextureImporterSettings` 读写 —— 直接写 `importer.spriteMeshType` 会编译报错（本轮踩过）。

**完整的地貌过渡仍留给迭代 4** —— H5 那套 `TILE_MASK` 自动拼接要么烘焙大图（显存代价如上），要么引入 Tilemap（新范式）。先不引入。

## 问题二：攻击后附近没敌人时角色卡在攻击帧

**性质**：真缺陷，判据写反了。

`PlayerController.Update` 里原本是：

```csharp
if (view != null && view.State != AnimState.Attack)   // ← 状态已是 Attack 时永远为 false
    view.Play(moving ? Walk : Idle);
```

攻击动画是**非循环** clip，播完后 `CharacterView` 只置 `IsFinished`、**不改 `state`**，所以 `state` 仍停在 `Attack`。于是这个分支永远进不去，角色僵死在攻击帧上。

- 附近**有**敌人时：`PlayerCombatController` 不断以 `restart: true` 重新触发攻击，看起来在正常射击，掩盖了问题
- 附近**没**敌人时：不再触发新攻击，状态就彻底卡住 —— 这正是用户看到的现象

**修法**：判据带上 `IsFinished`：

```csharp
bool attackPlaying = view.State == AnimState.Attack && !view.IsFinished;
if (!attackPlaying) view.Play(moving ? Walk : Idle);
```

**同类问题排查**：`EnemyController.UpdateView` 每帧无条件 `view.Play(AnimState.Walk)`，因为敌人从不播攻击动画（接触伤害是瞬时的），所以不受影响。但敌人的攻击动画目前**完全没用上** —— 属于待补的表现缺口，记在下方遗留里。

## 过程中的一次自伤

`Build Ground` 第一次是在 **Play 模式下**执行的 —— 运行时创建的对象会在退出 Play 时被还原，且 `MarkSceneDirty` 抛了 `InvalidOperationException: This cannot be used during play mode`（控制台里那条错误就是它）。

**教训**：编辑器工具类菜单项必须在**编辑模式**下执行。后续调用 `editor_execute_menu` 前应先确认 `editor_get_state` 的 `isPlaying` 为 false。本轮的补救是停 Play 后重跑 + `scene_save`。
