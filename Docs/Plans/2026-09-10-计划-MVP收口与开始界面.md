# 2026-09-10-计划-MVP 收口与开始界面

> 关联前序计划：`Docs/Plans/2026-09-07-计划-菌核狂潮MVP架构与迭代计划.md`
> 背景：迭代 0~5 已交付并留有独立日志，但对照 MVP「包含」清单仍有未交付项；用户试玩反馈「玩家死亡后游戏界面仍在活动」。

## 目标

补齐 MVP 计划范围内尚未交付的项，并新增「开始界面」，把原型收敛成一个**从开局到死亡重开、全流程无缺口**的最小可玩版本。

## 范围

### 包含

1. **开始界面（新增）**：极简形态——标题「菌核狂潮」+「开始游戏」按钮。点击前世界冻结：不刷怪、不计时、玩家不可移动。
2. **游戏阶段状态机**：新增 `GamePhase { Ready, Playing, GameOver }` 到 `IGameStateModel`，**取代**现有 `IsGameOver` 布尔，作为「当前处于哪个阶段」的唯一事实来源。前序计划第 3 节「数据归属」已把「游戏阶段」明确归入 Model，本次是把该设计补上。
3. **死亡冻结（修复用户反馈）**：玩家死亡瞬间冻结整个游戏世界——玩家停止移动、敌人停止追击、刷怪停止、投射物与掉落物静止。当前 `GameOverCommand` 只置了标志位，没有任何一处真正停下。
4. **HUD 经验条 + 等级显示**：前序计划「包含」清单中明确列出的「经验条」，当前完全缺失，玩家看不到升级进度。
5. **难度系统单一来源**：删除 `EnemySpawner` 中与 `DifficultySystem` 重复的刷怪间隔公式，统一由 System 层计算。
6. **升级保留溢出经验**：升级后不再把经验清零，保留超出阈值的部分，避免手感随等级陡增而变钝。
7. **升级事件化**：改用前序计划设计、但定义了从未被引用的 `OnLevelUpEvent` 通道，消除「面板直接监听 `Level` 属性」带来的误弹风险（迭代 5 修复 3 的根因即在此）。
8. **UI 预制体化（迭代 7 新增）**：开始界面与死亡重开界面由「代码建 UI」改为**预制体**，预制体实例直接放入场景；脚本只保留 `[SerializeField]` 引用。目的：UI 结构可在编辑器里直观调整，不必改代码。
9. **返回开始界面（迭代 7 新增）**：死亡面板新增「返回开始界面」按钮，提供「重开」与「回主菜单」两条路径。返回时**清空场地**（敌人/投射物/掉落物回收进对象池、玩家归位），并把阶段切回 `Ready`。
10. **UI 全面预制体化（迭代 9 新增）**：HUD 与升级三选一面板改为预制体，至此全工程四个界面（开始 / 死亡 / HUD / 升级）统一由预制体实例驱动，「代码建 UI」的写法彻底退场。附带在场景中补一个常驻 `EventSystem`。
11. **收尾清理**：移除残留调试日志；更新已过期的 `project-fingerprint.md`。

### 非目标

- 精英怪 / BOSS / 局外元进度 / 正式美术音效 / 存档 / 热更
- HUD 与升级三选一面板的预制体化（本次只做开始界面与死亡重开界面两个）

## 推荐推进方向

1. **先状态机后表现**：迭代 6 先把 `GamePhase` 立起来并让 5 处 Update 认这个状态，再加开始界面。顺序反了会出现「界面能点但世界仍在跑」的中间态，难以验证。
2. **死亡冻结用阶段门禁，不用 `Time.timeScale`**：现有 `UpgradePanelController` 已经在用 `timeScale` 做升级暂停，若死亡也改写 `timeScale`，升级面板选完技能时执行的 `Time.timeScale = 1f` 会把死亡状态一起解冻——两个功能会互相拆台。阶段门禁是单一事实来源，不与面板耦合。
3. **迭代 7 的事件化改造顺带消掉一类 bug**：面板从「监听 `Level` 属性」改为「监听升级事件」后，迭代 5 修复 3 里「重开时 `Level` 被置回触发面板误弹」的根因就从结构上消失了，`SetValueWithoutEvent` 降级为第二道防线而非唯一防线。
4. **每迭代一闭环**：按项目规则，每个迭代完成后写独立日志并经你确认再进下一个。

## 风险点

| 风险 | 影响 | 应对 |
|------|------|------|
| `IsGameOver` 被替换为 `Phase`，涉及 4 个文件的读写点 | 漏改会编译失败或行为异常 | 改动前全库 grep，替换后确认无残留引用；编译通过后再进 Play |
| 开始界面与死亡面板的 Canvas / EventSystem 叠加 | 可能出现多个 EventSystem 或面板层级遮挡 | 复用两个现有面板已有的 `EventSystem.current == null` 守卫；两面板分属 `Ready` 与 `GameOver` 阶段，天然互斥 |
| HUD 经验条与升级事件同时改动 | 经验条可能读到过期阈值 | 经验条显示用 `IUpgradeSystem.GetThreshold(当前等级)` 现算，不缓存 |
| 溢出经验保留后的等级判定 | 极端情况下可能一次加多级 | 当前掉落物每次只给 1 点经验、阈值最低为 5，单次升级不可能跨级；实现里在日志中保留可观测点，若后续调整经验数值需重新评估 |
| 运行态验证依赖编辑器实时连接 | 脚本重载期间 REST 会短暂中断 | 已实测确认 `unity-skills`（`127.0.0.1:8090`）连通正常：`surfaceProfile=full`、`currentMode=bypass`、编译空闲、Console 0 错误。重载导致的断连按协议等待 2–3 秒重试即可 |
| 自动化可验证「不报错」，验证不了「手感」 | 冻结是否彻底、经验条是否好看仍需人眼判断 | 迭代 6/7 的客观项走 REST 验证，主观项由你在编辑器内跑一局确认 |

## 验证方式

- 每迭代：Unity 编译通过（Console 无 Error）+ Play 模式运行态验证按上表「验证方式」列执行。
- 客观项通过 `unity-skills` REST 驱动编辑器验证（已在本次开工前实测连通）：`debug_get_errors` / `console_get_stats` 读 Console、`debug_check_compilation` 读编译状态、`find_objects_by_name` 核对场景对象、运行态截图辅助确认。按项目约定，引擎编辑器操作一律走该协议，不手工操作。
- 迭代 6 重点验证：进入 Play 后世界静止且开始界面可见 → 点击开始 → 移动/刷怪/攻击正常 → 死亡瞬间确认**玩家无法移动、敌人停止、刷怪停止**。
- 迭代 7 重点验证：HUD 显示等级与经验进度且随拾取增长 → 升级后经验不清零 → 刷怪间隔仍随时间缩短 → 升级面板正常弹出且重开不再误弹。
- 收口标准：完整跑通「开始界面 → 开局 → 移动 → 杀怪 → 升级三选一 → 死亡（世界冻结）→ 重开 → 再次可玩」一局。
