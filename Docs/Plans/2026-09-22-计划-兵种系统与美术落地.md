## 目标

## 关键前提（实测，与直觉不符）

这几条是本次所有决策的依据，写在最前面：

1. **工程里一个 Sprite 都没有。** 玩家/敌人/投射物/掉落物全是内置 Cube 网格 + Default-Material；所谓 Built-in 2D 实际是正交摄像机下的 3D 图元。
2. **碰撞全是手写距离判定**，`Collider2D` / `Rigidbody2D` / `OnTriggerEnter` 全工程出现 0 次。**换成 Sprite 后这些判定依然成立**（它们只读 `transform.position`），但硬编码的 `0.6²` / `hitRadius` 必须参数化，否则兵种的受击半径差异形同虚设。
3. **`.meta` 的 guid 被该引擎混淆**，与 YAML 内引用的 hex guid 无推导关系 → **绝不能手写 `.meta`**，一律让编辑器生成。
4. **`unity-skills` 建不了 AnimationClip**（`animator_create_clip` / `animator_add_clip` 不存在），也**建不了 SortingLayer**（`TagManager.asset` 只有 Default）。这两条决定了动画与排序方案。
5. **`transform.Translate` 默认 `Space.Self`** → **绝不能旋转根 Transform**，否则移动方向会被自身旋转二次旋转（表现为敌人绕圈、WASD 方向随瞄准漂移）。朝向必须落在子节点 `Visual` 上。

## 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 素材入库 | 先把 `Assets/Art/` 加入 `.gitignore` 保护；**待用户把公开仓库改为私有无误后**再移除该行并提交 | 仓库当前是公开的（匿名访问 HTTP 200），素材许可 R11 未读 |
| 精灵导入 | 拆成逐帧 PNG，**离线重采样到统一密度**，导入 `PPU = 100`（默认值） | `sprite_set_import_settings` 无批量版；526 个资产逐个改 PPU 需 526 次 REST 调用。改为"离线重采样 + 尺寸由 SO 的 scale 决定"后，导入只需 3 次批量调用 |
| 相机尺寸 | **保持 ortho size 5**（视野高 10 格） | 用户选择。H5 数值按比值传递，内部平衡不受影响；仅观感更近（角色占屏高 17.5% vs H5 的 7.8%） |
| 数值缩放 | **不做缩放**，H5 数值原样进 SO | 平衡是比值关系，同单位同比即保留。只需按视野重定场地尺寸与刷怪环 |
| 排序 | 全部留在 `Default` 层，用 `sortingOrder` | 无建 SortingLayer 的技能；改 `TagManager.asset` 风险不对称（层名写错会静默回落 Default） |
| 动画 | **脚本逐帧**（`CharacterView`），不用 Animator + AnimationClip | 无建 clip 的技能；H5 本就是帧号状态机可 1:1 复刻；80 敌时 Animator 开销明显；打击帧本就该按归一化时间轮询 |
| 攻击模型抽象 | System 层纯 C# `IAttackModel` + 两个面向 System 的接口（`IEnemyTarget` / `ICombatWorld`），由 Controller 实现 | System 不能引用 `EnemyController`；依赖箭头「Controller 实现 System 定义的接口」方向正确 |
| 确定性 | 在 `GameFlowController` 加 60Hz 固定步长累加器，攻击模型只消费 tick | 策划案 R7：扇形/锥形判定用 `deltaTime` 驱动会导致高刷机器命中结果不同 |

## 迭代 1 详展（兵种系统 + 美术替换）

### 1a 表现层改造

**统一结构：根节点 = 逻辑，`Visual` 子节点 = 表现。**

```
Player / Enemy / Projectile / ExpDrop（根：Transform + 逻辑脚本）
└── Visual   (SpriteRenderer + CharacterView)   ← 子节点索引固定为 0
    └── HpBar（敌人，迭代 2）
```

- 删掉四个对象上的 `MeshFilter` / `MeshRenderer` / **`MeshCollider`**（三个要一起删 —— MeshCollider 依赖 MeshFilter 的 Cube 网格）
- 旋转、翻转、缩放、偏移**全部落在 `Visual`**，根保持恒等旋转 → `Translate` 的 `Space.Self` 语义不变
- 朝向偏移：H5 的 `rot = aim − π/2` 是在画布 Y 向下坐标系实测的；**Unity 是 Y 向上，预期符号翻转为 `aim + π/2`**。必须按 4 方向截图矩阵实测后定，不要照抄

**锚点公式**（严格等价于 H5 的 `drawSprite`，是「攻击时人物不缩小」那条修复的 Unity 版）：

```
scale   = worldHeight × 100 / refH          // 逐角色一个值，落在 Visual.localScale
offsetY = (spriteWorldHeight − worldHeight) / 2
spriteWorldHeight = frameH / 100 × scale
```

> **核心断言**：同一角色在 idle ↔ atk 之间**脚底不移动、身体不变小**。这是 H5 commit `851b49b` 修掉的那个 bug，Unity 侧必须复现正确行为而不是复现 bug。

**排序表**（`SortingOrders` 静态常量类，全在 Default 层）：

| order | 内容 |
|-------|------|
| −1000 | 地面烘焙图 |
| −500 | 实体脚下阴影 |
| 0 | 掉落物 |
| 100 | 特效 |
| 200 | 敌人本体 |
| 230 | 敌人血条 |
| 300 | 投射物 |
| 320 | 玩家 |
| 400 | 挥砍弧 / 火焰锥 |
| 900 | 世界空间飘字 |
| 1000 | BOSS 屏幕外箭头 |

不做 Y 排序（H5 是纯画家序，保持 1:1）。将来若要做，用 `GraphicsSettings.transparencySortMode = CustomAxis(0,1,0)`，不要手写 `sortingOrder = -y*100`。

**相机**：`clearFlags` 改为 SolidColor + 深色背景（现为默认天空盒，精灵贴上去很怪）。`orthographicSize` 保持 5。

### 1b 兵种系统

**配置表**（`Assets/Configs/`，与 H5 的 `data.js` 一一对应）：

| SO | 数量 | 字段要点 |
|----|------|---------|
| `BodyDefinition` | 2 | baseHp / baseSpeed / damageMul / attackRateMul / hitRadius / worldHeight / refH / portrait / death 动画 |
| `WeaponDefinition` | 5 | model 枚举 / rate / range / dmg / arc / knock / projSpeed / pierce / shots / spread / burst / ammo / cone / burn / atkFrames / hitAt / icon |
| `CharacterSpriteSet` | 10 | idle / walk / atk 三段（各含 `Sprite[]` + 帧时长 + offsetX/offsetY + scale） |
| `ClassCatalog` | 1 | bodies[2] + weapons[5] + 枚举顺序约定，10 兵种由组合派生 |
| `GameConfig` | 1 | 场地尺寸 / 刷怪环 / 分离力 / 半径 / 经验曲线系数 |

**不建 `ClassSO`** —— 10 个兵种是笛卡尔积，策划案明确要求「不需要写 10 份配置」。

**四层落点**：

| 层 | 落点 | 内容 |
|----|------|------|
| Model | `IGameStateModel` 加 `SelectedClassIndex` | 与 `Phase` 同类：**`Reset()` 不碰它**（重开沿用同一兵种）。这条要写进注释，否则会被"顺手补上" |
| Command | 新增 `SelectClassCommand(int)` | 兵种面板只发命令，不直接写 Model |
| System | 新增 `IPlayerStatSystem` | 唯一的局内数值权威：由 (Body, Weapon) 派生基准值，再叠加全部可变量与限时 buff。纯 C# |
| System | `IUpgradeSystem` 改造 | 保留 `GetThreshold`；「3 张固定牌」换成按权重抽 3 张（迭代 7） |
| Controller | `PlayerController` / `PlayerCombatController` 改为**每帧从 System 拉取** | 删掉 `AddDamage` / `IncreaseFireRate` / `AddMoveSpeed` 这些"推"接口 —— 它们正是"重开必须逐项复位"的根源 |

**`StartNewGameCommand` 必须补第 7 步**：`GetSystem<IPlayerStatSystem>().Reset(body, weapon)`。**`GameArchitecture.Init()` 注册项从 4 变 5**。

### 1c 攻击模型

| 模型 | 覆盖武器 | H5 对应 |
|------|---------|---------|
| `ArcAttack` | 匕首 / 棒球棍 | 扇形角度筛选，动画到打击帧才结算 |
| `ProjectileAttack` | 手枪 | 单发投射物 |
| `BurstProjectileAttack` | 步枪 | 三连发 + 弹药消耗与回充 |
| `ConeAttack` | 火焰喷射器 | 锥形持续 tick + 燃烧 DOT |

**其他必改**：伤害与血量 `int` → `float`（H5 的 `8 × 1.10 = 8.8` 改 int 会丢掉男性 +10% 的意义）；`EnemyController.FindNearest` 加 `maxRange` 参数。

## 风险与依赖

| # | 风险 | 应对 |
|---|------|------|
| R1 | **仓库是公开的**，与用户「自用不会公开」的认知不符；素材许可 R11 未读 | 已告知；`Assets/Art/` 先加 `.gitignore` 保护，待用户确认改为私有无误后再移除并提交 |
| R2 | 拆帧会放大体积（跨帧压缩窗口被切开），估 20~30MB / 1000+ 文件 | 离线重采样到统一密度，可压 4~10× |

| R4 | 旋转根 Transform 导致移动方向错乱，且现象会被误判成 AI/输入 bug | 朝向只落在 `Visual`；写进注释与日志 |
| R5 | 朝向偏移符号照抄 H5（Y 轴方向相反，应为 `+π/2`） | 4 方向截图矩阵实测 |
| R6 | 攻击帧锚点漏了 `offsetY` → 角色下移（H5 那个 bug 的等价形态） | 断言 idle↔atk 脚底不动 |
| R7 | 对象池复用残影 | `EnemyController.Init` / `CharacterView.Reset` 显式复位全部可视状态（约定 §5 禁止增量更新导致残影） |
| R8 | 新增有状态 System 忘了在 `StartNewGameCommand` 补复位 | 把复位步骤改成带序号的显式清单 |
| R9 | `FixedUpdate` / `LateUpdate` 绕开「Update 首行门禁」这唯一机制 | 不引入 `FixedUpdate`；调试探针**有意不补**并写注释 |
| R10 | `0.6²` 参数化后接触距离从固定 0.6 变成 0.78~1.5，手感变化明显 | 单独测，别混在美术替换里归因 |
| R11 | **工程还没有中文字体**（策划案 R6） | 兵种选择界面立刻会撞上，需提前准备字体文件 |
| R12 | H5 的波次配额未回写策划案 | 迭代 3 的前置条件 |
| R13 | `com.unity.2d.sprite`（SpriteAtlas）不在 manifest | 526 个独立纹理无法合批；导入时先打 `packingTag` 留钩子 |

## 推荐推进方向

1. **素材先行且一次做对。** 迭代 0 把拆帧、重采样密度、导入设置、排序一次定死。任何一项错了，后面所有预制体都要返工。
2. **配置表先于玩法。** 迭代 1 建 SO 不只是为了兵种系统，它同时消掉「数值硬编码」这个既有遗留项。先有表，后面加武器/加敌人都只是加数据。
3. **先能切兵种、再做界面。** 迭代 1 用调试方式验证 10 个兵种都能正确工作，界面放到迭代 6。反过来做的话，界面做好了但逻辑没通，排查要在两层之间来回跳。
4. **敌人分级排在兵种之后。** 攻击模型定下来后，「什么敌人需要几发打死」才有基准，否则敌人数值要调两遍。
5. **地形风险独立，可并行。** 它是纯视觉、不影响逻辑，且工程没用过 Tilemap，是唯一需要新范式的部分，放并行位不会阻塞主线。
