# 菌核狂潮 · 可试玩原型

[`../index.html`](../index.html)（H5 策划案）的可运行版本。双击本目录的 `index.html` 即可开玩，**不需要本地服务器**（刻意没用 ES module，否则 `file://` 会被 CORS 拦住）。

## 依赖：素材不在 git 里

原型读取 `../assets/`（约 24MB）。这个目录**故意没有入库** —— 它是 craftpix 的商业素材，推到公开仓库等于再分发（见 `Docs/Current/project-fingerprint.md` 的「版本控制」节）。

**本机直接能玩**（素材在磁盘上）。但**把仓库克隆到别处会打不开**：界面能显示，游戏里所有精灵会消失。

恢复方式：按 `Docs/Design/README.md` 的说明重新生成 `assets/`，或从素材包手动复制。

> 缺失素材时不会白屏 —— 控制台会打印哪些素材加载失败，画面上角色会不可见但逻辑照常运行（`drawSprite` 对缺失精灵直接返回）。

## 操作

| 操作 | 键位 |
|------|------|
| 移动 | WASD / 方向键；移动端左半屏拖动为虚拟摇杆 |
| 攻击 | 自动瞄准最近敌人，无需按键 |
| 升级三选一 | ← → 或 1 / 2 / 3 选择，空格 / 回车确认（也可点击） |
| 暂停 | ESC |
| 静音 | 暂无开关（合成音音量已压到 0.10） |

## 实现了策划案的哪些部分

**兵种系统** —— 10 个兵种（角色 2 × 武器 5）全部可玩，动画直接用素材原始帧。

| 武器 | 攻击模型 | 实现方式 |
|------|---------|---------|
| 匕首 | 扇形瞬时 | `resolveArc` + 角度筛选，动画到打击帧才结算 |
| 棒球棍 | 扇形 120° + 击退 | 同上，额外给敌人一个衰减的击退速度 |
| 手枪 | 单发投射物 | 走对象池，可被「穿透弹」升级加穿透 |
| 步枪 | 三连发 | 连发用 `burstLeft` 计数，消耗弹药、缓慢回充 |
| 火焰喷射器 | 锥形持续 | 每 tick 做锥形筛选 + 叠燃烧 DOT，生成火焰粒子 |

**其余系统** —— 敌人 11 种（1~5 级含 3 只 BOSS）、11 波难度曲线（11 波后无限循环）、经验与升级、14 张升级卡（普通/稀有/史诗三档权重）、8 种掉落、对象池、BOSS 屏幕外指示箭头、死亡结算与评级。

**刻意对齐的两条工程约定**：
- **固定步长逻辑** —— 1/60 秒固定 tick，不用 `deltaTime` 直接驱动。这是策划案「核心战斗必须确定性计算」的落地方式。
- **对象池** —— 敌人 / 投射物 / 掉落 / 特效 / 飘字五类都走池，避免割草时频繁 GC。

## 与策划案的偏离（都标在代码注释里）

| 项 | 策划案 | 原型 | 原因 |
|----|--------|------|------|
| BOSS 血量 | boss1 2200 / boss2 2600 / mega 9000 | 900 / 1100 / 2600 | 策划案数值标注了「未实测」。以原型满配约 90~120 DPS 算，9000 血要打 75 秒以上，单局不成立 |
| 每波时长 | 未给 | 22~36 秒 | 补的空缺值，兼顾推到 BOSS 的节奏与单局时长 |
| 敌人分离力 | 「简单分离」 | 系数 3.2 | 初版 0.55 实测敌人全叠在玩家身上糊成一团 |

lv1~lv3 敌人的数值原样保留 —— 实测手感正常。

## 调试参数

URL 后面加查询串，用于自动化核对（无头浏览器 rAF 帧数很少，不这样做截到的永远是第 0 秒）：

| 参数 | 作用 |
|------|------|
| `?auto=N` | 跳过菜单，直接用第 N 个兵种开局（0~9） |
| `?ff=N` | 开局前同步跑 N 个逻辑 tick（60 tick = 1 秒）。升级时自动选第一张，以便跑到后期与死亡 |
| `?wave=N` | 直接跳到第 N 波 |
| `?dbg=1` | 左下角状态浮层 + 敌人位置红圈 |
| `?screen=pick\|help\|over\|pause` | 直接打开指定界面 |

例：`index.html?auto=2&wave=9&ff=420&dbg=1`

## 踩过的两个坑（改代码前先看）

1. **相机必须既 translate 又 scale。** `Camera.apply` 少了 `scale(PX_PER_UNIT)` 时，实体的**坐标**会被当成像素（只偏移几个像素，全挤在屏幕中心），而**尺寸**因为 `drawSprite` 里乘了 `PX_PER_UNIT` 反而是对的 —— 表现为「敌人逻辑上散开、画面上叠成一坨」，极易误判成 AI 问题。加上 scale 后相机内所有绘图一律用世界单位，想把东西画成 n 像素用 `px(n)`。
2. **俯视角精灵的朝向偏移是 `-π/2` 不是 `+π/2`。** 精灵在 `rot=0` 时正面朝画面下方（+Y = π/2），所以 `rot = aim - π/2`。写反了会整体差 180°。核对图见 `Docs/Design/_tools/out/rot_test.png`（可重新生成）。
