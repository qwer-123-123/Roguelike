# 项目约定

> Roguelike 项目的架构与约定基线。引擎相关规则按语义适用，不绑定具体路径。

## 1. 引擎约定

- 本项目为 **Unity（2022.3.62t11）** 项目，脚本语言 C#。
- 涉及引擎编辑器相关的操作，优先使用 **EngineSkill**（即 `unity-skills`，通过本地 REST API 驱动编辑器），不允许凭记忆或手工操作。
- 纯概念问答、不涉及编辑器状态的操作，可直接查阅技能文档，无需走 REST 协议。

## 2. 分层与边界

- 业务层依赖基础设施层；基础设施层不能反向依赖业务层。
- 通用框架不承载业务语义。
- 同一对象内优先直接调用；同一系统内优先事件或明确回调；跨系统通信才使用消息中心。

## 3. 游戏逻辑规范

- 核心游戏机制（移动、战斗、交互、判定等）必须是确定性计算，禁止随机数影响核心玩法结果。
- 状态变更必须通过明确的规则系统，禁止硬编码魔法数。
- 状态对象不得原地修改（无副作用原则），变更必须通过显式方法或副本替换。

## 4. AI 算法规范（Roguelike 相关）

- 搜索/决策算法必须有显式性能预算（深度、宽度、时间限制）。
- 状态评估函数必须保持对称性：交换双方视角应得到相反或可比较的分数。
- 状态拷贝必须使用高效的手动拷贝，禁止热路径 JSON 序列化。
- 新增算法前必须说明时间复杂度，禁止引入无剪枝的指数级搜索。

## 5. 渲染规范

- 渲染层只读游戏状态，不得反向修改业务逻辑状态。
- 渲染分层必须有明确的深度/层级约定，禁止越层访问。
- 渲染更新必须完整清除并重绘动态层，禁止增量更新导致残影。

## 6. 脚本/代码规范

- 公共 API 必须有文档注释（`/// <summary>`）。
- 跨模块调用优先使用事件/回调/接口，避免直接引用具体实现类。
- 通用工具代码不得承载业务语义。
